# FreeTier 2API 插件：渠道能力修正、链路修复与测速接入

## 范围与状态

保留用户已批准的全部范围；**唯一排除的是 CPA 认证文件卡片改造**。测速主入口按原图设在插件模型表右侧，账号行入口保留并共用弹窗。必要的 CPA 宿主 HTTP 桥修正仅补齐凭证代理继承，不涉及 CPA UI。临时 7899 清理继续保留。

本规格描述目标与验收约束，以下历史问题不是实时状态。当前产品整体验收尚未完成，所有票的验收项继续待核实。

## Problem Statement

操作者在 CPA 里使用 FreeTier 2API 插件时，遇到六类互相纠缠的问题：

1. **签到能力被写死成错的**。MiniMax Code 国内版在插件里直接返回「国内版暂无签到活动」，但上游实际有 7 天阶梯签到（`400/400/400/1000/400/400/1000`），接口结构与国际版一致，`claim` 实测返回 `claim_result=1`。操作者因此每天少领一次额度，且没有任何提示说明这是插件判断错误。

2. **模型目录与上游漂移**。AutoClaw 国内版用一张 2026-09 的静态快照，10 条里只有 4 条真实存在，还漏掉了 `zai_glm-5.3-flashx-legal`。操作者看到的清单看起来正常，点下去却不可用。

3. **测速结果被改写，丢失原始证据**。WorkBuddy 返回 `400 code=11158 model [kimi-k3.1-pro] is not allowed for user type [personal_free_user]`，原文已经说明了原因，但插件层把它折叠成自定义文案，操作者拿不到可搜索、可反馈给上游的原始报错。

4. **没有便捷的模型测速入口**。用户原图要求插件模型表每行右侧直接测速，并收紧左侧列宽；账号行快捷入口也保留。两处应共用选择凭证/模型和展示结果的弹窗。

5. **Qoder 正式链路缺少稳定分流**。立项时 CPA 指向临时 7899，受托管 7891 尚缺 Qoder 域名分流；部分已测节点出现 TLS 失败。需给 Qoder 国际版独立登记直连域名，并分别验证轮询、带身份接口与调用。历史失败只覆盖对应样本，不代表全部节点必失败。

6. **签到失败无法归因**。操作者需要一份跨渠道的签到实测结果，用来区分「上游真的没有活动」「窗口还没开」「凭证已失效」——这三类现在都显示成同一种失败，无法排查。

## Solution

- MiniMax Code 国内版按实测结果声明签到能力，与国际版走同一套流程。
- AutoClaw 国内版改为实时探测模型目录，与已有的国际版路径一致；探测失败时保留上次成功结果，不返回空清单。
- 测速结果原样展示上游状态码与响应正文，不做任何归类改写。
- 插件模型表每行右侧作为测速主入口，收紧左列；账号行入口保留并共用弹窗。固定当前行的模型或凭证，再选另一项，一次只测一个组合。
- 修复 Qoder 链路：正式出口加入 Qoder 域名直连兜底，CPA 指回受托管出口，清掉临时进程。
- 以全部已安装 vendor ID 跑实测矩阵，国内/国际分别抽首凭证；无凭证、未声明能力也占一行，结果落盘横向对比。

## User Stories

### 签到

1. 作为 CPA 操作者，我想让 MiniMax Code 国内版账号也能签到，这样我不用为了领额度再单独开官方客户端。
2. 作为 CPA 操作者，我想分清本次新领、已领无新增、窗口未开、当前无活动、凭证失效、网络失败和上游异常，这样不会把不同原因混成一种失败。
3. 作为 CPA 操作者，我想重复领取时看到幂等成功而不是报错，这样批量签到不会因为已经领过就中断。
4. 作为 CPA 操作者，我想在上游明确时看到签到「几点开」；未给时间时显示未知，而不是编造时刻。

### 模型目录

5. 作为 CPA 操作者，我想让 AutoClaw 国内版的模型列表与上游一致，这样我不会对着一个不存在的模型反复重试。
6. 作为 CPA 操作者，我想在上游模型目录接口临时失败时仍然看到上一次的可用清单，这样不会整片空白。
7. 作为 CPA 操作者，我想模型列表里能看到上游真实提供的全部条目，包括之前漏掉的那些，这样不用去官方客户端对照。

### 测速

8. 作为 CPA 操作者，我想在测速失败时看到上游原始报错，这样我能直接复制去搜索或反馈。
9. 作为 CPA 操作者，我想在插件控制台里对某条凭证的某个模型一键测速，这样我不用手写 curl。
10. 作为 CPA 操作者，我想测速时能选择具体凭证，这样我能定位是账号问题还是模型问题。
11. 作为 CPA 操作者，我想凭证在测速下拉里显示的是我自己设置的显示名，这样我改完备注还能认出来是哪条。
12. 作为 CPA 操作者，我想测速结果包含耗时，这样我能判断是慢还是不通。
13. 作为 CPA 操作者，我想测速结果包含基础响应内容（不是只有一个 200），这样我能确认模型真的回了话。
14. 作为 CPA 操作者，我想测速结果不要噪音（不要整段原始 JSON 刷屏），只留状态码、耗时、模型、正文关键片段，这样我能一眼看完。
15. 作为 CPA 操作者，我想在原图的插件模型表每行右侧直接测速，同时保留账号行快捷入口；两处共用同一个测速弹窗。
16. 作为 CPA 操作者，我想左侧既有列宽收紧一点，把空间让给测速按钮和结果区，这样表格不会挤成一条缝。

### 出口与链路

17. 作为 CPA 操作者，我想同一个供应商的国内版与国际版能各自走合适的网络出口，这样不会因为一条链路拖垮全部账号。
18. 作为 CPA 操作者，我想给单条凭证指定出口，这样某个账号需要特殊网络时不用改全局配置。
19. 作为 CPA 操作者，我想 Qoder 国际版走与其它渠道相同的出站机制，但它的域名在该链路上强制直连，这样我不必为它单独换节点。
20. 作为 CPA 操作者，我想 Qoder 的正式出口是受托管、开机自启的，这样机器重启后签到和对话不会突然全断。
21. 作为 CPA 操作者，我想临时验证用的进程在正式链路验证通过后被清掉，这样我不会对着两个端口猜哪个在生效。
22. 作为 CPA 操作者，我想测速接口的出站与生产请求完全一致，这样测速通过不代表生产会挂、测速失败也不会是测速自己的网络问题。
23. 作为 CPA 操作者，我想国内版走直连、国际版走代理，这个区分由凭证配置决定而不是写死在代码里，这样换环境不用重新编译。

### 维护

24. 作为维护者，我想签到能力有实测证据支撑，这样新增供应商时不会靠类推写出错误结论。
25. 作为维护者，我想各渠道签到结果落成一张表，这样「插件写错了」和「上游真没有」能一眼分开。
26. 作为维护者，我想模型目录只有一个来源（实时接口），这样上游改表后不用发版。
27. 作为维护者，我想测速展示层不承担翻译职责，这样新增错误码不需要改展示代码。
28. 作为维护者，我想保留请求覆盖、凭证出口、全局出口的继承关系，并把 Qoder 域名分流单独登记；补齐宿主 HTTP 桥后，日常出口调整只改配置。
29. 作为维护者，我想所有真实上游改动先在 lab 里跑通再进插件，这样我不会把猜测写进产品代码。

## Implementation Decisions

### 签到能力

- MiniMax Code 的签到能力不再按区域判断。国内版与国际版共用同一套签到流程，端点域名按区域选择。
- 签到分清本次新领、已领无新增、窗口未开、当前无可领活动、凭证失效、网络失败、上游业务异常；插件能力错误另列。窗口未开、无活动或发放未确认不记为成功；诊断尝试记录可保留。窗口时刻仅按上游明确证据展示。
- 签到能力声明必须有实测依据。新增供应商时先打接口验证，再声明能力。
- 逐 vendor 实例核验，不按品牌合并。覆盖基准见下方全渠道矩阵；已有能力按区域和账号如实报告。未声明能力只列现状，本次不额外新增签到能力。

### 模型目录

- AutoClaw 国内版改为走实时模型配置接口，删除静态模型表 `cnStaticModels`。
- 静态表仅在上游确实不存在模型清单接口时保留，且代码里必须写明原因与实测日期。
- 实时探测失败时保留上一次成功结果；首次探测失败返回空清单并给出可读原因，不编造条目。
- 模型目录与模型可用性是两个概念：目录说明「有哪些」，可用性说明「这条凭证此刻能不能跑」。目录里有不等于能跑。

### 测速展示

- 测速结果保留上游原始 HTTP/业务码与基础正文，不用二次文案覆盖；允许标注截断和秘密脱敏。
- 插件内部仍按错误类别决定账号处置（冷却、避让、禁用），但调度决策不进入展示层。
- 测速结果至少包含：是否成功、状态码、耗时、模型 ID、凭证标识、基础响应正文。
- 噪音过滤只做标注截断、无关字段裁剪与秘密脱敏：保留上游错误语义，不摘要成别的话。

### 出口策略

- 出口优先级固定为：请求级显式覆盖 > 固定凭证出口 > CPA 全局出口。必要的宿主 HTTP 桥改动负责补齐凭证出口透传与继承；插件侧复用该链路，不重复实现。此后端修正属于范围，不涉及 CPA 认证文件卡片 UI。
- 插件不按供应商硬编码出口。需要特殊出口时在凭证上配置，或在全局链路做域名兜底。
- 国内版直连、国际版走代理，这个差异落在凭证级出口上，不写成区域常量。
- Qoder 国际版独立特殊对待：它使用与其它渠道相同的全局出口链路，但 Qoder 三域在该链路上必须走直连兜底。这一条按渠道单独登记，不做成通用规则推导出来的结果。
- 域名直连按当前验证证据配置，记录所测节点、路径、轮次和时间；历史握手失败不外推全部节点或未来状态。
- 浏览器授权环节不在插件出站范围内：授权由操作者本机网络完成，插件只负责轮询与后续调用。

### 链路修复（7891 / 7899）

下表区分立项快照与交付目标；现场值每次从进程、服务、API 和容器核实。

| 端口 | 归属 | 立项问题与交付目标 |
|---|---|---|
| **7891** | `cpa-split-proxy.service`，受 systemd 托管 | 加入 Qoder 三域及子域直连；成为 CPA 正式统一出口；核验 enabled 与重启行为 |
| **7899** | 手工启动的临时分流进程 | 正式链路与业务验证通过后终止，核验端口释放；清理不删范围 |
| 7890 | 既有代理转发/Windows Clash 链路 | 保留原配置；记录实际上游，不把 WSL IP 或节点失败当恒定事实 |
| 41001 | `clash_1` 暴露端口 | 与本任务出口修复无关，不切节点、不改其配置 |

- 服务修改前保留可回滚备份；服务加载和重启后核验实际监听与路由。
- CPA 全局 `proxy-url` 通过管理 API 保存到 `http://127.0.0.1:7891`，保存后核验管理 API、容器文件、宿主文件三处。
- **2026-11-03 实施进展（执行者交接）**：已通过 `PUT /v0/management/proxy-url` 保存 7891 并回读确认。此前宿主配置原子替换 inode，容器单文件 bind 仍指向旧配置，所以容器/API 还显示 7899。线上 `codex` 的 `excluded-models` 比宿主多一项，已保留线上用户配置并同步宿主字节。私有备份位于 `/home/div/1_Project_dir/AI/CPA/freetier2api/.local/evidence/20261103`；容器尚未重建 bind。
- 维护时避免替换已挂载文件的 inode；由管理 API 保存后查三处真值。若存在旧 bind，先保留线上差异和私有备份，再处理文件同步/重建；本次文档更新不执行重建。
- 连通性验收记录完整 URL、出口、HTTP 状态与时间。Google 探测路径的 204、Qoder 页面 200、某路径 404 只证明各自请求结果，404 不证明账号授权通过。
- 业务验收另外验证带身份接口业务码、签到结果语义以及批准范围内的一次真实调用。HTTP 200 也不是签到到账依据。
- 回滚覆盖服务定义与运行配置；经 API 恢复前核对当前用户配置，不覆盖并行变更。正式链路通过后才清理 7899，并记录清理证据。

### 测速入口

- 测速入口做在插件控制台，不做在 CPA 的认证文件卡片。
- 固定凭证使用当前宿主明确支持的身份字段定位，校验 vendor 归属；不假设 auth_index 跨重扫稳定。持久显示身份以 file_id 为准，显示名仅作可见文案，不参与鉴权。
- 模型列表来源与插件模型页一致（含启用/禁用状态）。
- 一次测速只打一条凭证、一个模型，不做账号池轮换；通过可选 `request_stop` 禁止宿主及 Qoder 内层重试，不给诊断错误附加凭证冷却。
- 页面 90 秒由 AbortController 实际取消请求并解锁按钮，不靠未跨原生 RPC 的本地 deadline 冒充生效；晚到结果不覆盖取消状态。
- **主入口：插件模型表每行右侧**，按原图收紧左侧既有列宽，固定该行模型后选对应凭证。**账号行入口保留**，固定该行凭证后选模型。两个入口共用弹窗、请求流程与结果面板，不拆成两套功能。
- 凭证下拉的显示文案跟随操作者维护的显示名；显示名改动后下拉与结果面板都要立即反映新名字。
- 结果面板展示基础响应：状态码、耗时、模型 ID、响应正文关键片段；不展示与判定无关的噪音。

### 测速接口的出站一致性

- 测速与生产请求都走请求级覆盖 > 凭证级出口 > 全局出口的相同解析链；补齐 CPA 宿主 HTTP 桥凭证继承，并测试覆盖/继承/显式直连，范围仅后端。
- 测速不因为「只是测一下」就绕开凭证出口；否则测通的结果对生产没有参考价值。
- 供应商层面的特殊出口（如 Qoder 三域直连兜底）在测速链路上同样生效，不单独开例外。
- 测速失败时若判定为网络层不可达（连接建立失败、TLS 握手失败），结果里要能与上游业务错误区分开。

### 验证方式：lab 先行

- 所有涉及真实上游的改动，先在 lab 目录里用脚本走通，确认接口语义与失败形态，再落进插件代码。
- lab 验证要留下可复跑的脚本与结果文件，作为「这个结论从哪来」的依据。
- 未在 lab 跑通的路径不进入插件实现，避免把猜测写进产品代码。

### 签到实测

- 以运行时 `/vendors`、`/status` 枚举全部已安装渠道，国内/国际分别取按 `file_id`、`auth_id` 排序的第一把凭证；首凭证停用不换号，全池状态不由首凭证外推。
- 当前基准为 16 个实例，新增安装实例也要列入，避免只测七个品牌：

| 品牌 | 独立 vendor ID |
|---|---|
| AutoClaw | `autoclawcn`、`autoclawglobal` |
| CodeArts | `codearts` |
| MiniMax Code | `minimaxcodecn`、`minimaxcodeglobal` |
| Qoder | `qodercn`、`qoderglobal` |
| 小浣熊 | `raccoon` |
| Trae | `traecn`、`traeglobal` |
| WorkBuddy | `workbuddycn`、`workbuddyglobal` |
| Cline | `cline` |
| OpenCode ZEN | `opencodezen` |
| ZCode | `zcodecn`、`zcodeglobal` |

- 无凭证记「未测试」；未声明能力明确列出，不当失败。声明错误与上游实际结果并列，尤其 MiniMax 国内版预修复状态不能当无活动。
- 默认查资格/已领状态，明确可领且已经批准的每日奖励仅领取一次；不执行成长任务、模型生成、重登、付费动作或修改凭证来伪造签到成功。
- 小浣熊服务端每日发放/一次性登录奖励、WorkBuddy 国际版活跃次日奖励、ZCode 体验套餐分别说明，不与本次新领混淆。
- TSV 至少包含中文渠道名、vendor、区域、脱敏首凭证、实际出口、精确 endpoint、HTTP 码、业务码、上游基本消息、结果和时间；JSON/JSONL 保留结构化证据，无 token。
- 新领尽量记录奖励前后值和上游回执；已领明确无新增；`VIEW_DETAILS` 或 HTTP 200 均不计奖励。缺前值不编造增量。
- 窗口未开、当前无活动、凭证失效、网络失败、上游异常分别归类；范围只到该凭证/该路径/该时刻。
- 预修复报告保留原时间和出口差异，部署后另留验收证据；历史报告不覆盖成新结论。现场审计不替代离线回归与产品验收。

## Testing Decisions

**什么算好测试**：只断言外部可观察行为——给一份上游响应，插件产出的签到结果语义、模型清单、测速展示内容。不断言内部函数调用顺序、私有结构体字段或日志文案。

**测试接缝（沿用现有）**：

1. **供应商适配器接口**（`Checkin` / 模型清单拉取）。现有供应商测试已用假宿主注入上游响应，直接复用。观察点：
   - MiniMax 国内版凭证 → 走签到流程，产出已领取/窗口未开/凭证失效之一，而不是「暂无签到活动」。
   - AutoClaw 国内版凭证 → 发一次实时目录请求，清单与假响应一致；上游失败时回落到上一次成功结果。
2. **管理接口**（插件控制台 HTTP 层）。观察点：
   - 测速请求带凭证索引与模型 → 返回成功标志、状态码、耗时、基础响应正文。
   - 上游失败 → 成功标志为假，状态码与正文原样透出，不出现改写后的文案。
   - 凭证不存在或不属于该供应商 → 明确拒绝，不静默挑一条别的凭证。
   - 网络层不可达 → 结果可识别为网络问题，不与上游业务错误混淆。
3. **控制台页面**。模型表主入口与账号入口分别打开同一弹窗，预选项正确、凭证显示名更新、结果基础响应和窄窗口布局可读；沿用已有页面测试并补真人界面验收。CPA 认证文件卡片保持原样。
4. **宿主 HTTP 桥**。覆盖固定凭证代理继承、请求显式覆盖、全局回退与显式直连；实际出站与插件测速、签到一致。

**先例**：现有 Qoder 与 MiniMax 供应商测试已通过假宿主注入上游响应并断言结果语义，本次沿用同一形态，不新建测试框架。

## Out of Scope

**唯一排除项：CPA 认证文件卡片（认证文件管理页）的改造**，包括卡片备注、显示名、模型列、卡片内测速按钮与基础响应展示。

其它已批准范围全部保留。插件模型表主入口、账号行共用弹窗、凭证选择/显示名、基础响应、列宽调整、MiniMax 国内签到、AutoClaw 实时目录、逐 vendor 签到审计、Qoder 特殊域名直连、7899 清理及必要的宿主 HTTP 桥代理继承均在范围内。继承链补齐不等于 CPA UI 改造。

执行约束仍沿用：单凭证单模型、保留上游原文、不切订阅节点、不运行无关付费/成长任务；这些是实施方式，不是删减已批准范围。

## Further Notes

- AutoClaw 目录以带日期的 lab 上游结果及部署后复验为依据；保留历史样本，不把历史条目数量写成当前真值。
- MiniMax 国内版凭证有效性逐样本实测，不沿用「多数已失效」的旧概括。2026-11-03 早间首凭证状态可领，但部署能力仍 false；具体以原审计时间为界。
- 新领、已领、窗口、无活动、凭证、网络、上游与插件声明问题在表中分开；尚未完成的验收项保持未勾选。
- CPA 认证文件管理页不在本次范围。插件控制台与它是两套 UI，测速入口只做在插件控制台；两者若共用宿主探针接口，只对齐契约，不改 CPA 页面。
