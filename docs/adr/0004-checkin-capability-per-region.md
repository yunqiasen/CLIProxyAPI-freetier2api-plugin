# 签到按渠道实例与账号实测，分清新领与无新增

## 背景

MiniMax Code 国内版曾因区域开关被声明为无签到能力。2026-11-02 的上游证据显示国内版也有七天奖励序列 `400/400/400/1000/400/400/1000`；领取回执 `claim_result=1` 是本次新领，`2` 是已领无新增。2026-11-03 早间预修复审计又读到国内版今日可领，而当时部署能力仍为 false；两层事实应分别记录。

## 决策

- 能力按 vendor ID 与账号共同判定，国内/国际分别列项；以已安装 `/vendors` 和实际 `/status` 清单为覆盖边界，不用七个品牌代替全部实例。
- 结果至少分为：**本次新领、已领无新增、窗口未开、当前无可领活动、凭证失效、网络失败、上游业务异常**；能力声明错误、无凭证未测试、未声明能力也分别列项。
- HTTP 200、`VIEW_DETAILS`、活跃事件已上报均不等于领取成功；回执、状态变化、可取得的前后奖励数值一起留证。缺前值时不计算增量。
- 只有上游明确时间字段或活动规则时显示窗口开启时刻；其它情况报告时间未知，不套用 Qoder 的 10:00 规则。
- 窗口未开、当前无活动、发放未确认均不记为成功签到；诊断尝试记录可以保留，和成功记录分开。
- 默认先查资格与已领状态，仅对已批准、明确可领的每日奖励执行一次领取；不以生成模型请求、成长任务、重登或套餐购买代替签到。
- 服务端定时发放、一次性桌面登录奖励、次日活跃奖励和体验套餐与每日签到分开说明；本次不新增其能力。

## 后果

- MiniMax 国内版去掉错误区域拦截后仍需测试业务码、未知回执、已领与窗口分支；源码修改不等于上线验收。
- 无凭证记「未测试」，未声明能力记「未声明能力」，都不伪装成成功或上游无活动。
- 报告保存每渠道首凭证的确定性脱敏身份、区域、出口、精确路径、HTTP 码、业务码、上游基本消息、结果和时间。
- 本 ADR 已接受；当前整体验收继续待完成。
