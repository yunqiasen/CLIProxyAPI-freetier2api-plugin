# 测速展示上游原始报错，不改写语义

## 背景

WorkBuddy 免费账号请求 `kimi-k3.1-pro` 返回：

```
400 {"code":11158,"msg":"model [kimi-k3.1-pro] is not allowed for user type [personal_free_user]"}
```

曾考虑把它翻译成「当前账号等级不支持该模型」。这句话不增加任何信息——原文已经说明了账号类型不允许，改写反而丢掉 `11158` 和 `personal_free_user` 两个可检索的凭据。

## 决策

测速结果保留上游原始 HTTP 状态、业务码和基础正文；允许明确标注的截断与秘密脱敏，不用二次文案覆盖原文。网络错误在独立字段呈现，和上游业务错误分开。

主入口位于插件**模型表每行右侧**，按用户原图收紧左侧列宽；账号行入口保留，两个入口共用测速弹窗。模型入口固定当前模型后选凭证，账号入口固定当前凭证后选模型；一次仅调用选中组合。

唯一排除的页面改造是 CPA 认证文件卡片；必要的宿主 HTTP 桥凭证代理继承仍属后端交付范围。

普通生产请求仍按错误类别决定账号处置（冷却、避让、禁用）。测速是明确的诊断请求：保留分类前状态与正文，通过可选 `request_stop` 停止宿主重试，不轮换账号、不惩罚凭证；Qoder 的连接层及信封层也只调用一次。

页面通过 AbortController 在 90 秒取消测速请求并解锁按钮。取消结果不被晚到响应覆盖；该限制只针对插件测速，不新增生产模型超时。

## 后果

- 操作者拿到可复制、可搜索的原文，能直接对照上游文档或反馈给供应商。
- 展示层不再承担翻译职责，新增上游错误码不需要改展示代码。
- 分类字段可与原文并列，既保留定位依据，也区分网络/凭证/上游业务问题。
- 插件模型表主入口、账号入口、共用弹窗与正式请求链路都需验收；文档决策不等于已通过。
