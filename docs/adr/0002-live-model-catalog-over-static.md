# 模型目录以实时探测为准，静态表只在无接口时保留

## 背景

2026-11-02 排查时，AutoClaw 国内版有一张 10 条目的静态表，不发目录请求；当时样本暴露出名称失配和遗漏 `zai_glm-5.3-flashx-legal`。这些数量只描述历史样本，不是当前全量可用模型的承诺。

静态表与上游漂移后没有任何自愈路径，操作者只能看到一张看起来正常、实际不可用的清单。

## 决策

供应商若提供模型配置接口，以相应区域的实时目录为准，不用静态表替代；国内与国际实例分别核验。静态表仅在上游确实不存在任何模型清单接口时保留，且必须在代码里注明原因。

模型目录与模型可用性是两件事：目录说明「这个供应商有哪些模型」，可用性说明「这条凭证此刻能不能跑」。目录里有不等于能跑，测速才是判定手段。

## 后果

- 上游改表后插件自动跟随，无需发版。
- 目录请求需要缓存与失败回退：已有成功快照时保留该快照并说明本次错误；首次失败时明确报错，不伪造清单。
- 本次落地为 AutoClaw 国内版目录修正；保留既有全部批准范围，不把原则性说明扩成未经决定的全渠道重构。
- 决策接受不代表产品验收通过。
